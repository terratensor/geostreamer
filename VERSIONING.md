# Управление версиями GeoStreamer

## Обзор

Проект использует семантическое версионирование (SemVer) в формате `v<major>.<minor>.<patch>` (например, `v1.0.0`). Информация о версии внедряется в бинарный файл на этапе компиляции и доступна через флаг `-version`.

## Структура версии

Версия, выводимая программой, состоит из нескольких частей:
```
GeoStreamer v1.0.0-1-gd716e88-dirty (commit: d716e88, built: 2026-03-12_08:20:53)
```

Где:
- `v1.0.0` — семантическая версия из git-тега
- `-1` — количество коммитов после последнего тега (если есть)
- `-gd716e88` — сокращенный хеш последнего коммита
- `-dirty` — флаг, указывающий на наличие незакоммиченных изменений
- `commit: d716e88` — хеш коммита для точной идентификации
- `built: 2026-03-12_08:20:53` — время сборки

## Команды для работы с версиями

### Просмотр текущей версии
```bash
# Показать версию собранного бинарного файла
./geostreamer -version

# Показать версию из git (без сборки)
git describe --tags --always --dirty
```

### Создание новой версии

#### 1. Патч-релиз (исправление ошибок, обратно совместимые изменения)
```bash
# Переключиться на основную ветку и обновить её
git checkout main
git pull origin main

# Создать тег для патч-версии
git tag v1.0.1

# Отправить тег в репозиторий
git push origin v1.0.1
```

#### 2. Минорный релиз (новая функциональность, обратно совместимая)
```bash
git tag v1.1.0
git push origin v1.1.0
```

#### 3. Мажорный релиз (несовместимые изменения API)
```bash
git tag v2.0.0
git push origin v2.0.0
```

### Сборка с конкретной версией
```bash
# Сборка текущего состояния с версией из git-тега
make build

# Ручная сборка с указанием версии
go build -ldflags "-X github.com/terratensor/geostreamer/internal/version.Version=v1.0.0" -o geostreamer cmd/geostreamer/main.go
```

## Автоматическое определение версии

Версия автоматически определяется при сборке через `make`:

1. **Из git-тега**: если последний коммит имеет тег, используется он
2. **Из ближайшего тега**: если коммитов после тега несколько, добавляется счетчик и хеш
3. **Как `dev`**: если git-репозиторий недоступен

Примеры:
- `v1.0.0` — точное совпадение с тегом
- `v1.0.0-2-gabc1234` — два коммита после тега v1.0.0
- `dev` — при сборке вне git-репозитория

## Чекпоинты и версии

Каждый файл чекпоинта содержит версию программы, которая его создала:
```json
{
  "offset": 48276629,
  "line_number": 833854,
  "timestamp": "2026-03-09T23:55:49+03:00",
  "version": "v1.0.0"
}
```

Это позволяет:
- Отслеживать, какой версией создан чекпоинт
- При необходимости реализовать миграции между версиями
- Диагностировать проблемы совместимости

## Интеграция с CI/CD

В пайплайнах непрерывной интеграции рекомендуется использовать следующий подход:

```yaml
# Пример для GitHub Actions
- name: Get version
  id: get_version
  run: echo "VERSION=$(git describe --tags --always)" >> $GITHUB_OUTPUT

- name: Build
  run: |
    go build -ldflags "-X github.com/terratensor/geostreamer/internal/version.Version=${{ steps.get_version.outputs.VERSION }}" \
      -o geostreamer cmd/geostreamer/main.go
```

## Рекомендации

1. **Всегда создавайте теги для релизов** — это обеспечивает воспроизводимость сборок
2. **Используйте аннотированные теги** для добавления описания:
   ```bash
   git tag -a v1.0.0 -m "Release version 1.0.0: initial stable release"
   ```
3. **Проверяйте версию перед сборкой**:
   ```bash
   git describe --tags
   ```
4. **Для разработки используйте суффиксы**:
   - `v1.1.0-alpha.1` — альфа-версия
   - `v1.1.0-beta.2` — бета-версия
   - `v1.1.0-rc.1` — релиз-кандидат

## Устранение неполадок

### Версия отображается как `dev`
**Причина**: сборка выполнена вне git-репозитория или git недоступен.
**Решение**: выполните сборку в директории с git-репозиторием.

### Версия содержит `-dirty`
**Причина**: есть незакоммиченные изменения в рабочей директории.
**Решение**: закоммитьте изменения или используйте `git stash`.

### Тег создан, но версия не обновляется
**Причина**: новый тег не виден в локальном репозитории.
**Решение**:
```bash
git fetch --tags
git describe --tags
```
